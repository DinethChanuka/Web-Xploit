## 🔎 Overview

**WEB-XPLOIT** is a modular, terminal-driven penetration testing framework written in Python 3.13+. It scans a target host for open services and presents an interactive menu to run 60+ attack modules across MySQL, SSH, FTP, SMTP, HTTP/S, and a wide range of advanced network services — all with a rich, colorized CLI powered by [Rich](https://github.com/Textualize/rich).

Key highlights:

| Capability | Details |
|---|---|
| **Auto-recon** | TCP port scanner across 9 services; auto-detects service versions |
| **Full-Auto mode** | Chains all non-brute attacks bottom→top against a target, harvests credentials between modules |
| **IP rotation** | Spoofs `X-Forwarded-For`, `X-Real-IP`, `CF-Connecting-IP`, and 7 other headers + User-Agent on every HTTP request |
| **Result downloads** | All findings saved under `downloads/<host>/` tree, organized by service and port |
| **Multi-target** | Scan one host, then run a single attack type across *all* compatible targets simultaneously |

## ✨ Features

- 🔁 **60+ attack modules** across 9 protocol families
- 🤖 **Full-Auto & Auto-Pwn** — zero-interaction chained exploitation
- 🌐 **IP rotation** — header-level source spoofing on every HTTP request
- 🎨 **Rich TUI** — panels, progress bars, color themes, terminal-width-aware banners
- 📂 **Structured output** — per-host download tree with logs, dumps, and captures
- 🧩 **Plugin-style dispatch** — `DISPATCH` dict maps every `AttackType` → handler
- 🔙 **Back-navigation** — every menu prompt supports `GoBack` without crashing
- ⚡ **Configurable delay** — tunable inter-request delay to avoid rate-limiting
- 📋 **Wordlist support** — built-in `usernames.txt`, `passwords.txt`, `user_pass.txt`

## 🏗 Architecture

```
main.py                   ← Entry point, DISPATCH table, main loop
├── Design/
│   ├── header.py         ← ASCII banner renderer (Rich panels)
│   ├── colors_cli.py     ← Theme: primary / secondary / success / error / muted
│   ├── menus.py          ← render_menu() — numbered selection with back-support
│   └── prompts.py        ← ask_input() / GoBack exception
│
├── modules/
│   ├── port_scanner.py   ← TCP scanner → TargetInfo objects
│   ├── attack_menu.py    ← AttackType enum + per-service menus
│   ├── attack_config.py  ← AttackConfig dataclass + per-attack config wizards
│   ├── attack_registry.py← SERVICE_ATTACKS, ATTACK_LABELS, get_attacks()
│   ├── ip_rotate.py      ← X-Forwarded-For / User-Agent cycling
│   ├── reporter.py       ← Result formatting helpers
│   ├── downloads.py      ← downloads/<host>/ path management
│   ├── target.py         ← TargetInfo dataclass
│   └── attacks/          ← One file per attack family (see below)
│
├── wordlists/
│   ├── usernames.txt
│   ├── passwords.txt
│   └── user_pass.txt
│
└── App.json              ← Version + author metadata
```

### Data flow

```
main()
  │
  ├─→ port_scanner.scan_target()          → list[TargetInfo]
  ├─→ attack_menu.run_attack_menu()       → (target, AttackType)
  ├─→ attack_config.run_attack_config()   → AttackConfig
  └─→ DISPATCH[attack_type](target, cfg)  → runs the module
```

## 🚀 Usage

```bash
# Activate venv (if not already)
source .venv/bin/activate

# Run
python3 main.py
```

### Interactive workflow

```
1. Enter target IP / hostname
2. Select services to scan (or leave blank for all)
3. Port scanner auto-discovers open services
4. Pick a target + attack from the menu
5. Configure attack parameters via guided prompts
6. Review findings in downloads/<host>/
```

### Execution modes (multi-service targets)

| Mode | Description |
|------|-------------|
| **Single target + single attack** | Standard one-shot mode |
| **One attack across all targets** | Runs the same attack type on every compatible discovered service |

### Full-Auto example

```
Target: 192.168.1.100
Service: mysql (port 3306)

→ Selects FULL AUTO from menu
→ Chains: CONFIG_ENUM → MYSQL_AUTH_BYPASS → MYSQL_UDF → MYSQL_BACKDOOR → ...
→ Harvests credentials from log after each module
→ Passes harvested creds into next module automatically
```

## 🔧 Configuration

`AttackConfig` is the central configuration dataclass. It is populated via interactive prompts per attack type.

| Field | Default | Description |
|-------|---------|-------------|
| `username_mode` | `FIXED` | `FIXED` or `RANDOM_FROM_LIST` |
| `password_mode` | `FIXED` | `FIXED` or `RANDOM_FROM_LIST` |
| `charset` | `a-z0-9` | Brute-force character set |
| `max_length` | `6` | Maximum brute-force length |
| `delay` | `0.0` | Seconds between requests |
| `http_path` | `/` | Target HTTP path |
| `http_method` | `POST` | HTTP verb for form attacks |
| `http_params` | `q,id,search,page` | Comma-separated param names to fuzz |
| `http_use_tls` | `False` | Use HTTPS |
| `payload_type` | `php` | Shell payload language (php/jsp/asp/aspx) |
| `smtp_helo` | `test.local` | SMTP EHLO hostname |
| `log_file` | `None` | Path to save findings |

### IP Rotation

All HTTP modules automatically rotate headers on every request via `modules/ip_rotate.py`:

```python
# Headers injected on every request:
X-Forwarded-For, X-Real-IP, X-Originating-IP,
X-Remote-IP, X-Client-IP, CF-Connecting-IP,
True-Client-IP, User-Agent (random browser string)
```

IP pools rotate through APAC residential, US cable, European residential, cloud/CDN, and mobile ranges.
